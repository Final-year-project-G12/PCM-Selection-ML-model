## Overview: What These Plots Do

These comparison plots verify that the multi-phase Rajasthan PCM selection pipeline produces logically consistent results across clustering, feasibility screening, MCDM ranking, and physics validation stages.

**Key Principle:** If the pipeline is sound, relationships between variables should be stable and interpretable across clusters.

## Generated Plots (7/8 Complete)

### Plot 1: Cluster GHI Profiles ✅
**File:** `01_comparison_cluster_ghi.png`

**What it shows:**
- Mean GHI (global horizontal irradiance) per climate cluster with ±1 std error bars
- Compares the solar resource availability across the three climate regimes

**Why it matters:**
- Validates that climate clustering captured distinct solar radiation patterns
- Clusters with different GHI profiles justify different PCM selection strategies
- Cluster 0: Expected to have different solar profile than Clusters 1/2

**Data sources:**
- `climate_signature_rajasthan.csv` (GHI means)
- `cluster_assignments_rajasthan_levelB.csv` (cluster membership)

**Key interpretation:**
- Taller bars = higher solar resource
- Error bars show intra-cluster variability
- If all clusters have similar GHI, clustering may be less effective

### Plot 2: PCM Tm Target vs Cluster Temperature ✅
**File:** `02_comparison_temp_vs_tm_target.png`

**What it shows:**
- Scatter plot: X-axis = cluster mean ambient temperature, Y-axis = recommended PCM melting point (Tm)
- Each point represents one cluster (3 total)
- Red and green dashed reference lines show +25°C and +35°C offsets

**Why it matters:**
- A good PCM selection should have Tm = T_ambient + 25-35°C (rule of thumb)
- Validates that MCDM methodology produces thermodynamically sensible recommendations
- Deviations from this relationship indicate potential MCDM weighting issues

**Data sources:**
- `climate_signature_rajasthan.csv` (T_ambient per cluster)
- `feasibility_survivors_rajasthan_kappa_calibrated.csv` (Tm_target per cluster)

**Key interpretation:**
- Points near or on the +25/+35°C lines = good alignment
- Points far below line = PCM too cold (poor storage)
- Points far above line = PCM too hot (sensible-only heating, no phase change)

---

### Plot 3: MCDM Methods Side-by-Side (Top 5 per Cluster) ✅
**File:** `03_comparison_mcdm_methods.png`

**What it shows:**
- 3 subplots (one per cluster)
- Each subplot: 5 PCM candidates (ranked by Borda consensus)
- 4 grouped bars per candidate (TOPSIS, GRA, PROMETHEE II, VIKOR ranks)
- Lower rank = better candidate

**Why it matters:**
- Verifies that all 4 MCDM methods produce consistent rankings
- Identifies candidates with rank-agreement issues (crossing bars)
- Detects potential sign-inversion bugs in VIKOR (if bar patterns reverse)

**Data sources:**
- `mcdm_rankings_rajasthan.csv` (all ranking methods + consensus rank)

**Key interpretation:**
- Flat bar patterns across methods = strong consensus
- Crossing patterns = disagreement between methods (investigate weighting)
- If Borda-ranked #1 candidate has high VIKOR rank, may indicate VIKOR sign-inversion

---

### Plot 4: Monte Carlo Stability vs Consensus Rank ✅
**File:** `04_comparison_mc_vs_rank.png`

**What it shows:**
- Scatter plot: X-axis = consensus rank (1=best), Y-axis = Top-3 inclusion probability (%)
- Each point = one PCM candidate
- Colors = clusters; labels = PCM names

**Why it matters:**
- Shows robustness of MCDM rankings under Monte Carlo sampling uncertainty
- High inclusion probability (~80%+) = robust recommendation (appears in Top-3 most draws)
- Low inclusion probability (<20%) = fragile recommendation (rank sensitive to perturbations)

**Data sources:**
- `mcdm_rankings_rajasthan.csv` (consensus rank + MC inclusion %)

**Key interpretation:**
- Top-1 PCM should have >80% inclusion → rank = 1, inclusion ~80-100%
- Candidates with rank > 5 but high inclusion (~70%) = good alternatives
- Candidates with rank ≤ 3 but low inclusion (<50%) = weighting-dependent choices (investigate)

---

### Plot 5: Latent Heat Distribution (All vs Survivors) ✅
**File:** `05_comparison_latent_heat_distribution.png`

**What it shows:**
- Overlaid histograms: gray = all PCM candidates, blue = feasible survivors
- Normalized by density (area under curves = 1)
- Vertical dashed line = median latent heat of survivors

**Why it matters:**
- Confirms feasibility screening selected realistic PCM candidates
- Shows if survivor pool is balanced (not biased toward high/low latent heat)
- Indicates if L_required threshold is appropriate

**Data sources:**
- PCM database (all candidates)
- `feasibility_survivors_rajasthan_kappa_calibrated.csv` (survivors only)

**Key interpretation:**
- If survivor distribution is narrow, L_required may be too strict
- If survivor distribution overlaps with all-candidates, screening worked appropriately
- Median should be consistent with climate needs (higher L for cooler climates)

---

### Plot 6: Physics Validation vs MCDM Rank ✅
**File:** `06_comparison_physics_vs_rank.png`

**What it shows:**
- Two subplots (side-by-side):
  - Left: MCDM rank (X) vs. annual solar fraction (Y)
  - Right: MCDM rank (X) vs. complete charging cycles per year (Y)
- Each point = one PCM candidate; colors = clusters

**Why it matters:**
- **Critical validation:** MCDM top-ranked PCMs should deliver best simulated performance
- If higher-ranked PCMs have lower solar fractions, weighting matrix may be wrong
- Cyclical stability (complete cycles) indicates thermal robustness

**Data sources:**
- `mcdm_rankings_rajasthan.csv` (consensus rank)
- `physics_validation_rajasthan.csv` (annual solar fraction, cycles)

**Key interpretation:**
- Negative correlation (top-ranked = higher solar fraction) = valid MCDM
- Flat or positive correlation = weighting issues (investigate)
- Cycles per year: higher is better (more opportunities to charge/discharge)

### Plot 8: Rank Sensitivity to Weight Perturbation ✅
**File:** `08_comparison_rank_sensitivity.png`

**What it shows:**
- Line plot: X-axis = weight shift (0.3-0.7 range), Y-axis = combined rank (inverted)
- Each line = one PCM candidate (top 6 shown)
- Tests TOPSIS vs. GRA weight combinations

**Why it matters:**
- Measures robustness of top recommendations to weighting changes
- Flat lines = stable ranks (robust)
- Steep slopes = sensitive ranks (fragile, method-dependent)

**Data sources:**
- `mcdm_rankings_rajasthan.csv` (TOPSIS and GRA scores)

**Key interpretation:**
- Top-1 PCM should have flat line (remains #1 across weight shifts)
- If top-ranked changes significantly with weight shifts, recommendation is uncertain
- This sensitivity can inform whether to recommend single vs. multiple PCMs

## Troubleshooting

### "File not found" warnings
**Cause:** Data file doesn't exist at expected path  
**Fix:** Check data directory, verify file names match

**Expected files:**
```
data/processed/
  ├── climate_signature_rajasthan.csv
  ├── cluster_assignments_rajasthan_levelB.csv
  ├── cluster_profiles_rajasthan.csv
  ├── mcdm_rankings_rajasthan.csv
  ├── feasibility_survivors_rajasthan_kappa_calibrated.csv
  └── physics_validation_rajasthan.csv
```

### No plots generated
**Cause:** Missing required data files or column name mismatches  
**Fix:** 
1. Run Phase 5–9 pipeline to generate required outputs
2. Check column names in your data files
3. Add fallback column names to script if needed

### Empty plots or missing clusters
**Cause:** Data filtering removed all records  
**Fix:** Check if borda_score, consensus_rank, or other ranking columns are correct
